## 1. 版本与下载

### 1.1 只认一个来源

**<https://github.com/2dust/v2rayN/releases>**

> [!danger] ⚠️ 别从「下载站 / 网盘 / 免配置增强版」拿
> 论坛搬运、整合包最容易塞进旧内核、广告脚本甚至恶意文件。这个软件是开源的，官方 Release 免费、完整、还带 GPG 签名。

### 1.2 当前版本情况（2026-11 查）

| 项目 | 值 |
| --- | --- |
| 最新稳定版 | **7.25.6**（2026-10-11 发布） |
| 系统要求 | **Windows 10 及以上**（.NET 8 系） |
| 仓库 | <https://github.com/2dust/v2rayN> |
| 手机版 | 安卓用 [v2rayNG](https://github.com/2dust/v2rayNG)，iOS 用 Shadowrocket / Stash |

### 1.3 文件名怎么选

v7 之后命名统一了，**zip 就是便携版**（解压即用，配置存自己文件夹里，可以复制多份互相独立）：

| 你的机器 | 下载哪个 | 说明 |
| --- | --- | --- |
| **Windows 64 位（绝大多数人）** | **`v2rayN-windows-64.zip`** | WPF 界面，**已内置 Xray / sing-box / mihomo 内核** |
| 想试新界面 | `v2rayN-windows-64-desktop.zip` | Avalonia 实现的 UI |
| ARM 版 Windows | `v2rayN-windows-arm64.zip` | 兼容性一般 |
| 32 位 | `v2rayN-windows-86.zip` | 官方未验证，能用但别指望 |

> [!warning] ⚠️ 老教程的文件名已作废
> 网上很多教程让你下 `v2rayN-Core.zip`、`v2rayN-With-Core-win-64.zip`——那是 **v6 及更早**的命名。
> v7 的 `v2rayN-windows-64.zip` 本身就带内核，**不需要**再单独下 core。认错文件会导致版本混装。

`.sig` 后缀是 GPG 签名文件，普通使用可以不下载；想校验就用仓库 README 里的指纹。

## 2. 安装（解压即用）

1. 下载 zip → **解压到纯英文、无空格的固定目录**，例如 `D:\Apps\v2rayN\`
   - ⚠️ 别放 `C:\Program Files`（权限问题会干扰写日志、更新内核）
   - ⚠️ 别放桌面临时目录、同步盘（OneDrive/坚果云）目录
2. 双击 `v2rayN.exe`
3. Windows SmartScreen 提示「无法识别的应用」→ **更多信息 → 仍要运行**（开源工具通常没买签名）
4. 防火墙询问 → 允许**专用网络**（否则测速和代理都会超时）
5. 首次启动若提示缺 **.NET Desktop Runtime 8**，去微软官方装 x64 版：<https://dotnet.microsoft.com/download/dotnet/8.0>

> [!tip] 便携版的好处
> 配置（`guiNConfig.json` 等）都在程序文件夹里。
> - **备份 = 复制整个文件夹**
> - **多开 = 复制一份文件夹 + 改本地监听端口**（官方 FAQ 明确支持）
> - **更新 = 解压新的覆盖旧的**（先备份文件夹）

启动后程序不会自动开代理，只是驻留托盘——**不会**一上来就改你的网络设置。

## 3. 界面与核心选择

### 3.1 先认清「外壳」和「内核」

v2rayN 只是外壳，真正建立连接的是内核。v7 支持多内核切换，日常够用的三选一：

| 内核 | 适合什么 | 什么时候必须换 |
| --- | --- | --- |
| **Xray**（默认） | VLESS、REALITY、VMess、Trojan —— **3x-ui 出来的节点基本都吃这个** | 需要 Hysteria2 / MASQUE 时 |
| **sing-box** | Hysteria2、ECH、MASQUE、新传输 | 节点是 Hysteria2 却还停在 Xray，就会「全部超时」 |
| **mihomo** | 想要 Clash 那套 rule-set / 规则生态 | 手里有 Clash 规则需求 |

切换位置：**设置 → 核心设置 / 基础设置**（不同 7.x 小版本叫法略有差异）。

> [!important] 90% 的「导入后连不上」是内核和协议不匹配
> 先用默认 **Xray** 把 VLESS+REALITY 跑通，再考虑换内核。

### 3.2 界面能干什么（按功能找位置）

| 想做的事 | 位置 |
| --- | --- |
| 粘贴/导入节点 | 服务器列表区域，或「服务器」菜单 |
| 管理订阅 | 「订阅」菜单 → 订阅分组设置 / 更新订阅 |
| 选节点、看延迟 | 服务器列表（双击或右键启用） |
| 开系统代理 | 托盘图标右键 → 系统代理，或底部状态栏 |
| 开 TUN | 设置 → TUN 模式（v7 也可能在「系统代理」子菜单里） |
| 路由规则 | 设置 → 路由设置 |
| DNS | 设置 → DNS 设置 |
| 看日志 | 设置 → 日志 / `guiLogs` 文件夹 |

菜单名称在不同 7.x 版本有微调，**按功能找，别死记文案**。

## 4. 三种代理模式：先搞懂再动手

| 模式 | 覆盖谁 | 优点 | 代价 |
| --- | --- | --- | --- |
| **不改变系统代理** | 谁都不覆盖 | 不影响系统，可给别的软件手动填代理（`127.0.0.1:10808`） | 浏览器不会自动走代理 |
| **自动配置系统代理**（推荐日常） | 读系统代理的程序（浏览器、大多数应用） | 干净、可控、国内网站还能靠路由直连 | 游戏启动器、部分 UWP / Electron 应用不读系统代理 |
| **TUN 模式** | **整机流量**（网络层） | 管你是啥程序都能代理 | 需要管理员权限 + 虚拟网卡驱动（Wintun），可能和其他 VPN / 企业安全软件打架 |

### 4.1 日常：自动配置系统代理

托盘图标右键 → **系统代理 → 自动配置系统代理**。

> [!note] 官方 FAQ 提到的一个事实
> Windows 的系统代理**只能配 HTTP(S) 代理**，配不了 SOCKS5（Socks4 可以）。所以系统代理模式下是走本地 HTTP 端口（默认 10809），这不是 bug。

### 4.2 什么时候必须上 TUN

出现下面这些情况，别折腾系统代理了，直接 TUN：

- 游戏启动器（Steam / Epic / 各种 launcher）、某些客户端软件完全无视系统代理
- UWP / 商店应用、部分 Electron 应用不走代理
- 你希望**整机**按同一套路由规则走

开法：**以管理员身份运行 v2rayN** → 设置里打开 **TUN 模式** → 提示安装 **Wintun** 驱动就同意。

> [!warning] TUN 的三个坑
> 1. 不加管理员权限开不起来（或开了不生效）
> 2. 同时装了两个虚拟网卡类工具（另一款代理、企业 VPN、虚拟机网络）容易冲突
> 3. 开了 TUN 后要**先关掉系统代理**，两套一起开容易绕圈

### 4.3 本地端口

默认本地监听（Xray 内核）：

- SOCKS5：`127.0.0.1:10808`
- HTTP：`127.0.0.1:10809`

给不支持系统代理的软件（Git、IDEA、命令行）手动填这两个即可：

```bash
# Git
git config --global http.proxy http://127.0.0.1:10809
git config --global --unset http.proxy      # 取消

# PowerShell 临时
$env:HTTP_PROXY="http://127.0.0.1:10809"; $env:HTTPS_PROXY="http://127.0.0.1:10809"
```

## 5. 导入节点的三种方式

### 方式 A：从剪贴板粘贴（最快）

1. 在 3x-ui 面板：入站 → 客户端 → **复制链接**（得到 `vless://...` 一整行）
   → [[escape/3x-ui 安装与使用.md#9. 客户端与订阅|3x-ui 笔记 §9]]
2. 回到 v2rayN，在服务器列表处 **Ctrl+V**（或「服务器 → 从剪贴板导入」）
3. 列表里出现节点 → 双击选中 → 开代理

也支持一次粘贴多行（批量 URL）。

### 方式 B：手动逐项填（调试时最有用）

「服务器 → 添加 [VLESS] 服务器」，对着 3x-ui 的入站参数填：

| v2rayN 字段 | 从 3x-ui 哪里拿 |
| --- | --- |
| 地址 / Address | 服务器 IP 或域名 |
| 端口 / Port | 入站端口（如 `443`） |
| 用户 ID / UUID | 客户端的 `id` |
| 流控 / Flow | `xtls-rprx-vision` |
| 传输协议 / network | `tcp` |
| 传输层安全 / security | `reality` |
| SNI / serverName | `realitySettings.serverNames[]` 里的一个 |
| 公钥 / PublicKey (pbk) | `settings.publicKey` |
| 短 ID / ShortId (sid) | `shortIds[]` 里的一个 |
| 指纹 / Fingerprint (fp) | 通常 `chrome` |
| 加密 / encryption | `none` |
| allowInsecure | **false**（不要勾「跳过证书验证」） |

> [!tip] 为什么值得会手动填
> 链接坏了、参数被截断、客户端报「配置无效」时，手动填一遍能立刻定位到底是哪个字段错。

### 方式 C：订阅（多节点 / 多设备推荐）

见下一节。

## 6. 用 3x-ui 的订阅（推荐）

### 6.1 在 3x-ui 侧先准备好

- 订阅服务已开启（默认开）
- 订阅端口（默认 **2096**）已在**三层**都放行
  → [[escape/3x-ui 安装与使用.md#6. 端口放行：面板端口 ≠ 节点端口|3x-ui 笔记 §6]]
- 客户端的 **subId** 拿到了

订阅地址形如：

```
http://123.45.67.89:2096/<subPath>/<subId>
```

### 6.2 在 v2rayN 侧添加

1. 「订阅 → 订阅分组设置 → 添加」
2. 填 **地址**（上面那串）、**备注**（如 `Oracle-大阪`）、**自动更新间隔**（建议 6–12 小时）
3. 保存 → 「订阅 → 更新订阅（不通过代理）」

> [!tip] 先「不通过代理」更新一次
> 刚开始还没节点可用，走代理更新订阅必然失败。第一次务必选「不通过代理」。

### 6.3 端点选择（跟客户端有关）

| 客户端能力 | 用哪个 URL |
| --- | --- |
| v2rayN（Xray 内核，原始链接） | 面板给的基础订阅路径 |
| 想用 Clash / Mihomo 规则 | `.../<subPath>` 换成 `/mihomo/<subId>`（若面板启用） |

> [!warning] 订阅是明文 HTTP 时
> 订阅内容包含节点凭据。局域网 / 公共 Wi-Fi 下用 `http://` 订阅等于公开。给 3x-ui 的订阅端口配 TLS，或至少别在不可信网络里更新。

### 6.4 订阅更新后节点归零？

按顺序查：① 订阅地址是否过期/被改（浏览器直接打开看有没有内容）② subId 是否正确 ③ 客户端是否已到期或超流量 ④ 2096 是否还通。

## 7. 打开代理并验证

1. 服务器列表里**双击**一个节点（后面出现勾/高亮即为当前节点）
2. 托盘右键 → **系统代理 → 自动配置系统代理**
3. 验证：

```powershell
# 看本机出口 IP 是否变成服务器 IP
curl -s https://api.ip.sb/ip
# 或浏览器访问 ip.sb / ipinfo.io
```

4. 打开几个目标网站确认能正常加载（别只看一个站，有的站本身对机房 IP 不友好）

> [!note] v2rayN 退出时
> 正常退出会尝试关掉系统代理。**但如果直接关机/强杀**，系统代理可能残留，下次开机没跑 v2rayN 就会「上不了网」。
> 遇到这种情况：Windows 设置 → 网络和 Internet → 代理 → 关掉手动代理。

## 8. 分流：只让该走代理的走代理

### 8.1 先用内置模板

「设置 → 路由设置」里通常有：

- **绕过大陆（bypass mainland）**：国内域名/IP 直连，其余走代理 —— **日常首选**
- **全局**：全部走代理
- **仅代理局域网/不回环**：特殊场景

### 8.2 自定义规则（想更细时）

核心思路：把命中的域名/IP 分流到不同 `outboundTag`（`direct` / `proxy` / `block`）。一条最小可用的「国内直连」规则：

```json
{"outboundTag":"direct","domain":["geosite:cn"],"ip":["geoip:cn","geoip:private"]}
```

常见组合：

| 场景 | 规则思路 |
| --- | --- |
| 国内网站直连 | `geosite:cn` + `geoip:cn` → `direct` |
| 局域网/打印机/NAS 不动 | `geoip:private` → `direct` |
| Steam 下载走直连 | 域名命中 Steam CDN → `direct`（社区有现成规则） |
| 某站强制走代理 | 该域名 → `proxy` |
| 屏蔽广告域名 | 广告域名 → `block` |

> [!warning] 规则调试原则
> **一次只改一条**，改完马上测网页 + 测速 + 测本地服务。
> 一贴一大段规则、同时改 DNS 和模式，最后根本不知道哪步坏 —— 这是新手最常见的自坑方式。

## 9. 测速与「能连但不通」的判断

### 9.1 两种延迟，含义完全不同

| 测试 | 测的是什么 | 怎么用 |
| --- | --- | --- |
| **TCP / Tcping 延迟** | 到服务器端口的 TCP 握手 | 只说明端口通，**不代表节点可用**（REALITY 参数错也能通） |
| **真连接延迟** | 真正跑一次代理请求 | ✅ 这个通了才叫能用 |

操作：右键节点 → 「测试服务器 Tcping 延迟」/「测试服务器真连接延迟」。
真连接测试需要内核能起来；报「运行 core 失败」见下一节。

### 9.2 「能连但不通」怎么判

```
真连接延迟有数值？
├─ 有 → 节点没问题，问题在客户端配置：系统代理没开 / 路由把目标判成直连 / DNS 污染
└─ 没有 → 节点侧问题：
        - REALITY 的 SNI / pbk / sid / flow 是否和面板一致
        - 443 是否真的放行（三层都要）
        - 客户端内核是否支持该协议（Hysteria2 要 sing-box）
        - 服务器时间是否正确
```

## 10. 常用设置

| 需求 | 怎么做 |
| --- | --- |
| 开机自启 | 设置 → 参数设置 → 开机自动运行 |
| **手机共用电脑的代理** | 设置里开「**允许来自局域网的连接**」+ 放行 Windows 防火墙入站 + 手机填 `电脑IP:10809` |
| 多开多个实例 | 复制程序文件夹 → 改各自本地端口 |
| 备份 | 直接复制整个 v2rayN 文件夹 |
| 看详细日志 | 设置 → 日志等级改 Debug；界面日志 + `guiLogs` 文件夹 |
| 换托盘图标 | 往程序目录放 `NotifyIcon1.ico` ~ `NotifyIcon4.ico` |
| 流量统计 | 主界面底部有上/下行速率与累计 |

> [!tip] 局域网共享的正确姿势
> 「允许来自局域网的连接」只是让监听从 `127.0.0.1` 变成 `0.0.0.0`；
> 真正能不能连上，还要看 **Windows 防火墙入站规则**有没有放行 10808/10809（专用网络）。

## 11. 排障手册

| 现象 | 最可能的原因 | 处理 |
| --- | --- | --- |
| 启动报缺 .NET | 没装运行时 | 装 .NET Desktop Runtime 8 (x64) |
| 打开就闪退 | 目录权限 / 中文路径 / 杀软拦截 | 换到 `D:\Apps\v2rayN`，加杀软白名单 |
| 订阅更新出 0 个节点 | 地址过期、subId 错、客户端过期/超流量 | 浏览器直接打开订阅 URL 看内容 |
| 节点全部超时 | 内核和协议不匹配（Hysteria2 还在用 Xray）、防火墙拦了核心 | 切 sing-box 内核；放行程序联网；重启 v2rayN |
| 测真连接报「运行 core 失败」 | 配置无效、内核不支持、**本地端口被占用**（虚拟机/其他代理） | 日志等级调 Debug 看报错；改本地端口；关掉占端口的程序 |
| 浏览器能用，其他软件不行 | 该软件不读系统代理 | 开 TUN 模式 |
| 开了代理反而上不了网 | 系统代理残留 / 路由全走了代理 / DNS 污染 | 关系统代理重开；恢复「绕过大陆」路由 |
| 只有某个网站打不开 | 该站封机房 IP，或路由判错 | 单独把该域名指到 `proxy`；换节点 |
| 用了半天突然断 | 节点被封 / IP 被限 / 服务器出口限制 | 换节点或换端口；看 3x-ui 侧 `x-ui log` |
| 关机后没跑 v2rayN 就上不了网 | 系统代理残留 | Windows 代理设置里关掉手动代理 |
| 时间不对导致 TLS 失败 | 系统时间漂移 | 开启 Windows 自动同步时间 |

> [!tip] 反馈问题给作者时的正确姿势
> 先删旧日志 → 重现问题 → 提供步骤 + 日志。
> v2rayN 自身问题看 `guiLogs` 文件夹；内核问题看主界面信息栏的日志。

## 12. 手机 / 其他平台

| 平台 | 客户端 | 备注 |
| --- | --- | --- |
| Android | **v2rayNG**（同作者）、Hiddify、NekoBox | 直接粘贴分享链接 / 扫二维码 / 加订阅 |
| iOS | **Shadowrocket**（付费）、Stash、Loon、Hiddify | 需要外区 Apple ID |
| macOS | v2rayN（有 mac 版）、Clash Verge Rev、Stash | v2rayN mac 版 dmg 未签名，需 `xattr -cr` |
| Linux | v2rayN（deb/rpm/zip）、Clash Verge Rev | zip 版 `chmod +x v2rayN` 后运行 |
| 路由器 | OpenClash（Mihomo 内核） | 用 3x-ui 的 `/mihomo/<subId>` 订阅最省事 |

同一个 3x-ui 面板可以给多台设备各发一个客户端（各拿自己的 UUID/subId），再配合 `totalGB` / `limitIp` 做限流
